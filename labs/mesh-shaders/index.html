Mesh shader lab

A mesh shader pipeline stops drawing one big index buffer. The mesh is cut ahead of time into small pieces called meshlets. A task shader then decides, per meshlet, whether it is worth drawing at all, and a mesh shader turns each surviving meshlet into vertices and triangles.

meshlets (built offline)→task shader→mesh shader→rasterizer→fragment
Browsers cannot run mesh shaders: WebGL 2 has none, and for WebGPU they are still an open feature request. This lab runs the same pipeline by other means. JavaScript builds the meshlets and does the task shader's culling. A vertex shader does the mesh shader's work by reading the meshlet buffers from textures. One real difference: a mesh shader transforms each meshlet vertex once, while this emulation transforms it once per triangle corner.

Scene

1. Meshlet builder (offline step)

2. Task shader: which meshlets are worth drawing?

The task shader runs once per group of meshlets. It tests each one against the camera and emits mesh shader work only for the survivors. Culled meshlets cost nothing after this point: no vertex is transformed for them.

3. Mesh shader: meshlet in, triangles out

One mesh shader run handles one meshlet. It loads the meshlet's vertices, transforms them, and writes the triangle list as small local indices. It can also write values per triangle, with no vertex duplication. The Triangles and Meshlets stages are colored that way.
